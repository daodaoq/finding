# Finding 产品功能文档（详细版）

> 面向团队新同学与产品/开发协作的产品功能全览（PRD 级）。本文档描述**当前最新功能**，随代码同步更新。
> 技术实现见 `docs/design-manual.md`，领域术语见 `CONTEXT.md`，接口见 Knife4j（后端 `/doc.html`）。

---

## 1. 产品定位与用户角色

**Finding** 是山东理工大学校园社交平台，解决三类诉求：**看校园动态、找搭子一起玩、相亲交友**，配完整运营后台。

| 角色 | 能力边界 |
|------|----------|
| **游客** | 浏览动态/搭子/搜索结果；互动（点赞/关注/报名/申请等）触发登录弹窗；**相亲推荐需登录** |
| **未认证用户** | 登录后可用：浏览、点赞、关注、编辑资料、搜索；**发帖/评论/搭子/私信/相亲需先完成学生认证** |
| **已认证用户** | 全部功能 |
| **管理员** | 登录 `finding-admin`，负责审核、封禁、内容与运营管理 |

> 关键设计：所有权限与隐私规则**由服务端最终裁决**，前端只做展示投影（后端不下发的字段前端无法看到）。

## 2. 用户端功能详解

### 2.1 首页 / 校园动态

#### 信息流
- **热门 Tab**：子排序支持「按浏览量」「按点赞数」「综合推荐」（点赞×0.6+浏览×0.3+评论×0.1）。
- **最新 Tab**：按发布时间倒序。
- **关注 Tab**：仅展示已关注用户的动态（需登录，未登录空态）。

#### 动态卡片
作者头像/昵称 + 时间 + 学校/位置 + 正文 + 最多 9 图 + 点赞/评论数 + 匹配标签（热门/置顶）。

#### 发布动态（入口：底部 + → 发帖子）
1. 需登录且**已认证**；编辑正文（≤5000 字）+ 最多 9 张图 + 位置（选填）。
2. 提交后**敏感词分类**：
   - 命中拦截词 → 拒绝发布，提示具体违禁词；
   - 命中送审词 → 进入**待审**，仅作者可见，管理员后台过审后可见；
   - 干净 → 直接发布。
3. 图片仅接受**平台上传地址**（`/api/v1/images/`），后端校验数量/长度/来源；存储为 JSON，含逗号的 URL 也能完整保存回显。

#### 编辑 / 删除
- 仅作者可编辑/删除自己的动态；编辑后重新走敏感词审核。
- 删除为软删除（`status=0`），详情/评论/点赞/回复均按不存在处理。

#### 动态详情
浏览（浏览量 **1 小时窗口去重**，Redis 不可用降级累加）、点赞（切换式，通知作者）、评论。

#### 评论与回复
- 两级嵌套：一级评论 + 每条最多展示 3 条子回复（可展开总数）。
- 评论需已认证；内容敏感词拦截。
- **回复校验**：父评论必须属于当前动态且未删除，跨动态/已删除父评论被拒。
- 删除评论为软删除，前端显示「该评论已删除」占位（保留其下子回复）。
- 通知：被评论者（帖主或父评论作者）收到通知；评论点赞通知评论作者。

#### 游客限制
未登录仅可见前 5 条动态，登录后看全部。

### 2.2 找搭子（广场）

#### 分类
9 大分类（3×3 网格）：旅游 / 拼车 / 健身 / 学习 / 备考 / 运动 / 游戏 / 娱乐 / 其他。

#### 列表与筛选
- 排序：**时间最近**（活动时间最近优先，自动过滤已过期）或**距离最近**（需授权定位，Haversine 计算）。
- 筛选：关键词、地点、时间（今天/7 天/30 天内）、仅看有空位、仅看匿名。

#### 发布邀约（入口：底部 + → 找搭子）
分类 + 标题（≤100）+ 描述（≤2000）+ **活动时间**（本地时间，无时区偏移；必须晚于当前 30 分钟）+ 地点（≤200）+ 人数上限（2-50）+ 可选**匿名发布**。发布走敏感词分类（标题/描述/地点一并清洗，送审进后台审核）。

#### 参与流程与状态
```
申请加入(可留言≤500) → 发起人收通知 → 通过/拒绝 → 申请人收结果通知
满员 → 自动进入候补 → 有人退出 → 按申请时间顺序自动补位(并通知补位者)
```
- 报名状态：`待处理 / 已通过 / 已拒绝 / 已退出 / 候补 / 已失效`。
- 同用户对同一邀约不可重复报名；被拒/退出后需冷却（24 小时）才可再报。
- **名额防超卖**：通过申请时用「名额<上限」原子条件更新，并发下不会超卖；重复通过/拒绝/退出不会重复改名额。

#### 编辑 / 取消 / 停止报名
- 发起人可编辑（重新审核）、取消（删除）、停止报名（关闭，待处理/候补申请置为已失效并通知）。
- 活动过期/关闭后：不可报名、不可改参与关系、退出不再释放名额。

#### 地点脱敏
发起人和**已通过成员**可见精确地点 + 经纬度；其他人（含待审/被拒/匿名活动观众）只显示「报名通过后可查看集合地点」。**所有出口统一走同一权限策略**，避免某接口泄露。

#### 拉黑联动
双方任一方拉黑：不能查看对方活动详情、不能报名、已有参与关系失效。

### 2.3 相亲交友（鹊桥）

完整闭环：**推荐 → 申请 → 审批 → 会话 → 信息互换 → 情感简历**。这是项目特色模块。

#### 2.3.1 推荐流（单卡滑动）
- **一次只推荐一个用户**。卡片展示：照片（大图）+ 昵称/年龄/性别 + 学校/城市/距离 + 认证徽标 + 交友目标（找对象/交朋友）+ 自我介绍 + 匹配理由 chips（同校/同城/已认证/兴趣相投/偏好同校等）+ 最近在线。
- **❤️ 爱心** → 直接发送聊天申请（成功后换下一个）；**✖️ 叉号** → 标记不感兴趣，换下一个。
- 已申请/已跳过的用户不会重复出现；全部刷完显示「没有更多推荐了」。
- **反馈闭环算法**：推荐排序参考你的申请/跳过历史——
  - 你常申请的学校/城市 → 同校/同城候选加分（卡片显示「偏好同校/偏好同城」）；
  - 你常跳过的学校/城市 → 同校/同城候选减分；
  - 新用户（无历史）→ 冷启动优先已认证、近期活跃的候选。
  - 权重全部可配置（`finding.recommend.*`）。

#### 2.3.2 我的卡片（自定义展示）
用户自定义**自己在别人眼里长什么样**（入口：相识页「心动匹配 → 我的卡片」）：
- **12 个展示项开关**：照片 / 昵称 / 年龄 / 性别 / 学校 / 城市 / 距离 / 认证标识 / 交友目标 / 自我介绍 / 匹配理由 / 最近在线。
- 开关按**多张卡片分组**：资料卡（照片+昵称+年龄+性别+学校+城市+距离+认证+目标）、介绍卡（自我介绍）、标签卡（匹配理由）、活跃卡（最近在线）。
- 顶部**实时预览**「别人视角里的我的卡片」；保存后推荐流按此裁剪字段（隐藏的项别人看不到；只在可见性投影之上更保守，不会反向暴露）。

#### 2.3.3 聊天申请与审批
- **发起申请**：向推荐中的用户发聊天申请（可写备注，敏感词过滤）。
- **对方加好友方式**（`好友设置`）：
  - `0=自动同意` → 立即通过并建立会话；
  - `1=需对方同意（默认）` → 通知对方审批；
  - `2=拒绝新的聊天申请` → 直接拒绝。
- **状态机**：`待处理 → 已通过/已拒绝/已撤回/已过期`。
  - 同方向同时只有一条待处理（唯一约束防并发重复）；
  - 被拒/撤回后 **7 天冷却期**不能重发；
  - 待处理 **7 天**未处理自动过期。
- **审批**：仅接收方可操作；审批时再次校验双方账号状态/拉黑，异常则申请作废。通过后：建唯一会话 + 系统消息「已同意申请，可以开始聊天了」+ 双方自动互相关注 + 通知申请人。
- **申请列表**：我发出的 / 我收到的，按状态筛选（待通过/已通过/已拒绝/已撤回/已过期）+ 分页加载更多。失败场景（冷却/拉黑/已处理/账号异常）透出具体原因。

#### 2.3.4 信息互换与情感简历
- **信息互换**：需**先建立聊天关系**（任一方向有已通过的聊天申请）。发起 → 对方同意/拒绝 → 互换解锁。有频率限制（1 小时 10 次）；拉黑后待处理互换作废、已互换资料不再可见。
- **情感简历**（入口：我的 → 情感简历）：8 大板块 + 生活相册——
  1. **基础信息栏**：性别/年龄/生日/星座/身高体重/校区年级/家乡/职业/作息/恋爱状态/择偶底线
  2. **自我画像**：MBTI/性格/恋爱中的样子/缺点/三观/个人标签
  3. **过往恋爱复盘**：恋爱次数/分手原因/感情缺点/感悟/成长
  4. **恋爱相处模式**：日常陪伴/吵架方式/表达爱/异性边界
  5. **个人生活与规划**：日常/习惯/短期/长期/爱好/婚恋规划
  6. **理想另一半**：硬性条件/软性期待
  7. **加分项**：能带给对方什么
  8. **走心宣言**：爱情期待/爱情态度
  - 互换前对他人**锁定**（未互换只看到锁定状态）；互换后解锁查看。
  - 保存校验：文本长度/身高体重范围/生日为年龄唯一来源/相册数量与 URL；并发首存唯一键冲突自动回查更新。

#### 2.3.5 相亲偏好
性别（不限/男/女）/ 年龄范围（0-100）/ 最大距离（0-10000km）/ 只看已认证 / 偏好城市 / 交友目标 / 资料完整度门槛（0-10）。用于推荐候选过滤，含完整边界校验。

### 2.4 消息 / 聊天

#### 消息中心
两层结构：**通知中心**（未读角标）+ **私聊会话列表**。

**通知类型**（服务端下发）：

| 类型 | 触发 |
|------|------|
| `like` | 有人赞了我的动态/评论 |
| `comment` | 有人评论/回复了我的动态或评论 |
| `follow` | 有人关注了我 |
| `mate_request` | 有人申请加入我的搭子 |
| `mate_accepted` / `mate_rejected` | 我的搭子申请被通过/拒绝 |
| `mate_cancelled` / `mate_admin_closed` | 搭子被取消/管理员关闭 |
| `chat_apply` | 收到聊天申请 |
| `chat_approved` / `chat_rejected` | 我的聊天申请被通过/拒绝 |
| `info_share_request` / `_approved` / `_rejected` | 信息互换申请/结果 |
| `system` / `system_announcement` / `system_warning` | 系统公告/警告 |

#### 私聊
- **会话建立**：仅能通过「相亲申请审批」建立（不能随意对陌生人建会话）；双方自动互相关注。
- 会话列表：置顶/免打扰/隐藏会话；未读红点；新消息自动恢复隐藏会话。
- **消息**：文本/图片；WebSocket 实时推送（应用内即时）；已读回执；消息撤回（双方可见「已撤回」）。
- **聊天信息页**：查找聊天记录（关键词搜索）、对方名片、置顶、免打扰、设置聊天背景（预设/上传）、清空聊天记录、隐藏会话、投诉。
- **发送限制**：需已认证；同一用户短期高频发消息受限流保护。
- 拉黑后：双方消息不可互发、会话被隐藏。

#### 群聊
创建群、群信息（群名/头像/公告/成员）、群成员列表（可 @）、群内消息（文本/图片/撤回）。

#### 聊天设置（全局，我的 → 设置）
- **聊天设置**：全局消息免打扰、全局默认聊天背景（预设/上传，未单独设置背景的聊天使用）。
- **好友设置**：加好友方式（自动同意/需对方同意/拒绝新的聊天申请）。
- **隐私设置**：允许被搜索（`searchable`，关闭后不出现在用户搜索与相亲推荐，不删除已有关系）；主页可见性（所有人可见/仅已互换信息可见）。
- **相亲偏好**：见 2.3.5。

### 2.5 我的 / 个人中心

#### 资料卡
头像 + 昵称 + 学校 + 签名 + 个人背景图（可编辑）；**统计三项**：**关注**（followingCount）/ **粉丝**（followerCount）/ **好友**（互关数，mutualCount），点击进入对应列表（可关注/取关）。

#### 情感简历
见 2.3.4。

#### 菜单
- **我的动态 / 我的点赞 / 我的圈子 / 历史记录**（浏览记录，点击回跳动态或用户）
- **我的预约**（加入的搭子）/ **订单**（搭子按进行中/已结束筛选）
- **我的投诉**（投诉记录 + 处理状态）
- **帮助与客服**：常见问题（FAQ）/ 联系客服 / 使用指南 / 人工服务
- **设置**、**关于我们**、**退出登录**

#### 学生认证
提交真实姓名 + 学号 + 学校 + 学生证照片（选填）→ 管理员审核 → 通过解锁全部功能；被拒可查看原因重新提交。认证状态：未认证 / 审核中 / 已通过 / 已拒绝。

#### 投诉
可对消息、动态、评论、用户、简历发起投诉（选原因 + 补充说明 + 证据），后台处理。

## 3. 管理后台功能详解（finding-admin）

管理员用 `13800000000` 登录（密码 `12345678`）。

| 模块 | 详细功能 |
|------|----------|
| **数据面板** | 用户数、今日动态、搭子数、待审核数等统计卡片 |
| **用户管理** | 搜索/查看用户、封禁/解封 |
| **实名审核** | 待审/已通过/已拒绝 Tab；查看认证材料（姓名/学号/学校/学生证）；通过/拒绝（附原因） |
| **动态管理** | 动态列表/查看；**动态审核**：待审内容过审/拒绝（拒绝附原因，作者可见）；隐藏/删除 |
| **评论管理** | 评论列表与删除 |
| **搭子管理** | 搭子列表/查看；**搭子审核**：待审过审/拒绝；取消/关闭活动 |
| **举报处理** | 查看举报（类型/目标/证据）、处理（封禁/结案） |
| **申诉处理** | 内容审核申诉的处理 |
| **聊天审计** | 私聊消息审计 |
| **违禁词管理** | 违禁词增删改；动作：拦截（拒绝发布）/ 送审（进入待审） |
| **群管理** | 群聊列表与成员管理 |
| **相亲推荐管理** | 推荐相关运营管理 |
| **公告** | 系统公告的新增/编辑/删除（普通弹窗 / 永久顶部横条） |
| **横幅** | 首页轮播图的新增/编辑/删除/排序 |
| **反馈** | 用户反馈工单处理 |

| 领域 | 状态 |

| 举报 | `0=待处理 / 1=已处理 / 2=驳回` |

## 5. 核心业务规则速查

| 领域 | 规则 |
|------|------|
| 认证 | 发帖/评论/搭子/私信/相亲需实名认证；未认证只读 |
| 拉黑 | 双向任一方拉黑即生效：不能搜索/推荐/关注/申请/私信/看详细资料；隐藏双方已建会话；已互换资料不再可见；不删除历史消息 |
| 聊天申请 | 冷却 7 天、同方向待处理唯一、7 天过期；审批通过建唯一会话 + 自动互关 |
| 信息互换 | 需先有聊天关系；同意后解锁对方情感简历；1 小时限 10 次 |
| 搭子名额 | 原子条件更新防超卖；满员进候补按申请顺序补位 |
| 地点脱敏 | 发起人/已通过成员见精确地点，其余模糊；统一权限策略 |
| 推荐 | 基于申请/跳过历史的反馈闭环；游客不可见真实推荐；卡片按用户自定义裁剪 |
| 内容 | 动态/搭子走敏感词拦截+送审；图片仅平台地址（≤9 张） |
| 浏览 | 浏览量 1 小时窗口去重 |

## 6. 页面路由表（用户端）

| 路由 | 页面 |
|------|------|
